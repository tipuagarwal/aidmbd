Automation pays off when it removes work that is repetitive, rule-based and frequent. It disappoints when it's pointed at the wrong task, built too big too early, or left running with nobody watching it. Before you buy a tool or hire anyone, spend an afternoon working out what to automate first.

## Start with a week of honest notes

For one normal week, write down every task that feels repetitive. Keep it simple: what the task is, how often it happens and roughly how long it takes each time. You're looking for patterns, not perfection.

Typical entries look like this:

- Copying enquiries from the website form into a spreadsheet
- Sending the same reminder before every appointment
- Typing invoice details into the accounts system
- Building the same sales report every Monday

By the end of the week you'll have a list that's more honest than any guess, because it's based on what actually happened.

## Run each task through five questions

Not every repetitive task is a good first candidate. Score each one against these questions:

1. **Does it happen often?** A task done fifty times a week is worth more than one done once a month.
2. **Are the rules clear?** If you can write the steps down without saying "it depends", a workflow can probably follow them.
3. **Is the input digital and structured?** Form submissions and spreadsheets are easy. Handwritten notes and phone calls are not, at least not yet.
4. **What does a mistake cost?** A wrong reminder time is annoying. A wrong payment amount is serious. Start where mistakes are cheap and easy to spot.
5. **Will the volume grow?** If the task will double as the business grows, automating it now stops a problem before it arrives.

Tasks that score well on all five are your shortlist.

## Good first candidates

For most small businesses, the best first projects look similar:

- **Lead capture.** Every enquiry from your website, Facebook or WhatsApp lands in one place, tagged with where it came from.
- **Follow-up and reminders.** Appointment reminders and follow-up emails go out on schedule, without anyone remembering to send them.
- **Order and booking notifications.** Customers and staff get the right message when an order or booking changes.
- **Data extraction with review.** Details are pulled from invoices or forms automatically, and a person checks them before they're used.
- **Routine reports.** The Monday report builds itself from the data you already have.

Each of these is small enough to build and test in days rather than months, and each one saves time every single week.

## Keep a person in the loop where it matters

Automation should take the boring work away from people, not the judgement. Decide up front which steps need a human:

- Messages to customers about money, complaints or refunds
- Anything with legal or financial consequences
- Situations the workflow wasn't designed for

A good automation knows when to stop and hand over. An AI assistant that isn't confident in an answer should pass the conversation to a person, with the history attached, rather than guess.

## Plan for things going wrong

Every workflow fails eventually: an app changes its API, a form adds a field, a service goes down. Before you switch anything on, decide:

- **Who owns it.** One named person gets the alerts and fixes problems.
- **How you'll know.** Failed steps send an alert instead of failing silently.
- **What happens meanwhile.** There's a manual way to do the task until the workflow is fixed.

Logs that show what ran and when make problems far quicker to diagnose.

## Count the full cost

The saving is easy to estimate: hours saved each week, multiplied by what those hours cost. If a task takes three hours a week, that's roughly 150 hours a year.

The costs need the same honesty. Include:

- The setup work, whether you build it yourself or pay someone
- Tool subscriptions, which are usually monthly
- API or AI usage, which grows with volume
- Maintenance, because workflows need occasional fixes

If the saving clearly beats the running costs within a few months, it's a good project. If it's close, choose a different task first.

## Work in this order

1. Map the process as it really runs today.
2. Pick one task from your shortlist.
3. Build the smallest version that works, with a person approving the important steps.
4. Run it for a month and measure the time saved and the errors caught.
5. Only then expand it, or move on to the next task.

Starting small means you learn what automation does well in your business before you depend on it.
